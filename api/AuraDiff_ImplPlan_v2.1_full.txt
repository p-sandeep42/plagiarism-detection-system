P1-E  [NEW] Batch UI Components
[NEW] components/batch/BatchUploadZone.tsx  ← extracted from page (was missing)
Separating the upload zone into its own component keeps batch/page.tsx readable and makes the zone independently testable.

Props: onFilesAccepted(files: File[]): void, maxFiles: number
Features: drag-and-drop via HTML5 API, click-to-browse fallback, file type guard (.py .js .txt .pdf .docx), file count badge, remove-individual-file button
Show a filename chip for each accepted file. Derive student name from filename (strip extension, split on _ or -)
Framer Motion: each chip animates in with layout animation (AnimatePresence + motion.div)
If files.length > maxFiles: show inline error badge, disable submit CTA
Do NOT put axios/fetch calls in this component. It is display-only.

[NEW] components/batch/BatchErrorBoundary.tsx  ← was missing from original plan
Wraps StudentMatrix so a single-file parse failure cannot crash the entire /batch page.


[NEW] components/batch/StudentMatrix.tsx
Renders the N×N pairwise heatmap grid. Full specification from SOP §5.2, with corrected prop interface:

Props: data: BatchComparisonResponse, onStudentClick(studentIndex: number): void
Grid: CSS Grid with auto columns. Column/row headers = student names.
Cell colour: score < 0.30 → bg-green-100, 0.30–0.60 → bg-yellow-100, 0.61–0.79 → bg-orange-100, >= 0.80 → bg-red-200
Diagonal: render '--' in slate-300, no click handler
Hover tooltip (Tailwind group-hover): shows winnowing / structural / semantic breakdown
Click: calls onStudentClick(row_index) — the panel shows the clicked student's data
Sort toggle: button to sort student rows by max_score desc / alphabetical
Export: 'Download CSV' button — generates pairwise matrix as CSV client-side (no API call)

[NEW] components/batch/StudentDetailPanel.tsx
Side-drawer with 3 tabs. Critical correction: Tab 2 must explicitly map PairScore fields to SplitView props — the original plan omitted this mapping.


Remaining StudentDetailPanel specifications:
Props: studentIndex: number, data: BatchComparisonResponse, parsedTexts: string[], onClose(): void
Tab 1 — Score Overview: renders <Dashboard> with worst-case PairScore injected as scores prop
Tab 2 — Side-by-Side: renders <SplitView> using mapping above
Tab 3 — All Comparisons: table of all peers sorted by pairwise score desc + mini progress-bar per row
Animation: Framer Motion — initial={{ x: '100%' }} animate={{ x: 0 }} exit={{ x: '100%' }}
Backdrop: semi-transparent slate-900/60 overlay behind the panel, click-away closes
Header: student name, filename chip, risk-level badge (colour matches matrix cell colour)


P1-F  [NEW] frontend/src/app/batch/page.tsx
The batch route page wires everything together. Keep this file thin — all complexity lives in the sub-components.

Imports: BatchUploadZone, BatchErrorBoundary, StudentMatrix, StudentDetailPanel
State: files[], batchResult: BatchComparisonResponse|null, selectedStudent: number|null, isLoading: boolean, progress: {completed,total}
On mount: open WebSocket to /ws/batch-progress?token=SESSION_TOKEN; update progress state on each message
On submit: call getBackend().compareBatch(files), set batchResult
Render sequence: (1) BatchUploadZone, (2) progress bar (visible only when isLoading), (3) BatchErrorBoundary > StudentMatrix, (4) StudentDetailPanel (conditional)
SEO: export const metadata = { title: 'Batch Compare | AuraDiff', description: '...' }
