§4  Firebase-Ready Backend Architecture [SKILL:FIREBASE]

4.1  Abstraction Layer

4.2  Firebase Cloud Function Specification
If Firebase is chosen, the Cloud Function must mirror the FastAPI endpoint contract exactly. AI must implement the following function signature:
Function name: compareDocuments (callable)
Input: { fileA: base64string, fileB: base64string, fileTypeA: string, fileTypeB: string }
Output: ComparisonResponse (identical schema to FastAPI — see §6.1)
Timeout: 540 seconds (max) — semantic model loading requires extra time
Memory: 2GiB — required for sentence-transformers inference
Runtime: Python 3.11 — use functions-framework

4.3  Firestore Schema (Optional Caching)
To avoid re-running expensive semantic comparisons, results can be cached in Firestore using a content-hash key:
Collection: comparison_cache
Document ID: SHA-256(fileA_content + fileB_content) — computed server-side
Fields: scores (map), highlights (array), created_at (timestamp), ttl (7 days)
AI must add cache-check logic to the Cloud Function BEFORE running algorithms



§5  Multi-Student Batch Comparison Feature [SKILL:MULTI-COMP]
This is the most important new feature in this SOP. It transforms AuraDiff from a pairwise tool into a classroom-scale plagiarism detection system. AI must follow every specification exactly.


5.1  User Experience Flow
User navigates to /batch
Multi-file drop zone accepts N files (PDF, DOCX, .py, .js, .txt). Maximum 30 files per batch.
User clicks 'Run Batch Analysis'. Progress bar appears with live percentage.
Result: a Student Matrix Grid — N×N grid of pairwise similarity scores.
User clicks any student's name/card to expand their individual detail panel.
Detail panel shows: the student's highest-plagiarism match, full Dashboard.tsx score breakdown, and SplitView.tsx comparison against the most-similar peer.

5.2  Student Matrix Grid — Component Specification
The StudentMatrix component (components/batch/StudentMatrix.tsx) is the primary UI for the batch feature.


5.3  StudentDetailPanel — Component Specification
When a user clicks a student name in the matrix, StudentDetailPanel (components/batch/StudentDetailPanel.tsx) slides in from the right as a side-drawer.
Header: student name, file name, overall risk level badge (Low/Medium/High/Critical)
Tab 1 — 'Score Overview': renders existing Dashboard.tsx with the student's worst-case pairwise scores injected as props
Tab 2 — 'Side-by-Side': renders existing SplitView.tsx comparing the student's file against their highest-matching peer
Tab 3 — 'All Comparisons': table listing every peer, their pairwise total_score, and a mini bar chart
Animation: Framer Motion slide-in from right (x: '100%' → x: 0) with backdrop blur overlay

5.4  Backend: /compare-batch Endpoint

5.5  Performance Strategy for Batch
Parallelise algorithm runs: use Python asyncio + concurrent.futures.ThreadPoolExecutor
Cache parsed file content in memory per request to avoid re-parsing
Semantic model loaded once at startup (app startup event), not per-request
WebSocket endpoint /ws/batch-progress streams { completed, total, current_pair } JSON messages
Frontend uses native WebSocket API (not socket.io) to display live progress

§7  Project Scaling & Production-Readiness
7.1  Backend Scaling
Containerise FastAPI with Docker — provide Dockerfile in repo root
Use Gunicorn + Uvicorn workers: gunicorn -k uvicorn.workers.UvicornWorker -w 4
Load the sentence-transformers model once at startup; use model pool if multi-worker
Add Redis caching layer for repeat comparisons (key = hash of both file contents)
Deploy on Cloud Run (GCP) or Railway.app for automatic horizontal scaling

7.2  Frontend Scaling
Enable Next.js ISR (Incremental Static Regeneration) for the /about page
Use Next.js Image Optimisation for all team photos and OG images
Bundle analysis: run next build && npx @next/bundle-analyzer — target < 150kB first load JS
CDN: Deploy on Vercel; configure Cache-Control: s-maxage=3600 for static assets

7.3  Monitoring & Observability
Add Sentry for both Next.js (client+server) and FastAPI error tracking
API latency tracking: log p50/p95/p99 for /compare and /compare-batch
Vercel Analytics for Web Vitals (CWV) tracking in production

7.4  Extensibility Checklist for New Algorithms
When adding a 4th algorithm, AI must follow this exact checklist to prevent breaking existing functionality:
Create backend/algorithms/new_algo.py with a function compare(text_a, text_b) -> float
Add new_score field to ComparisonResponse in schemas.py
Update main.py weight dict: ensure all weights still sum to 1.0
Add new_score to Dashboard.tsx radar chart data array
Add new highlight colour token to design tokens (§1.1)
Update SplitView.tsx legend
Add unit test in tests/test_new_algo.py
